# Frontend Design

Adapted from `Enixes/astra-frontend-design` and `PaulRBerg/agent-skills`.

## Contract

Read the existing stack, assets, tokens and validation commands before changing the UI. Preserve working behavior and existing constraints unless the task explicitly changes them.

Before styling, define:
- visual thesis
- hierarchy
- type roles
- color roles
- spacing/density
- layout principle
- signature element
- motion level

Apply a subject-swap critique: if a major visual decision would work unchanged for any unrelated business, question it.

Build real controls, semantic HTML, keyboard focus, readable contrast, reduced-motion behavior and content-driven responsive constraints.

Finish with rendered inspection at representative widths and fix visible defects rather than declaring success from source code alone.

## PASS
Subject-specific visual direction, coherent implementation, semantic/accessibility baseline and browser-rendered verification.
