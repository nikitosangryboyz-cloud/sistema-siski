# Niche Architecture

Inspired by subject-specific product reasoning in `Enixes/astra-frontend-design` and `PaulRBerg/agent-skills`.

## Workflow

1. Identify business, audience and primary conversion/job.
2. List real products/services and proof available.
3. Identify user questions, objections and decision criteria.
4. Build a section map that answers those questions in a logical narrative.
5. Map each section to the established reference visual language.
6. Define CTA locations and functional states.
7. Avoid generic section quotas: a block exists only if it serves the page job.

## Output
`architecture/site-map.md` with section purpose, content inputs, CTA, required assets and dependencies.

## Hard rules
Never invent testimonials, metrics, certifications, guarantees, product capabilities or customer names.

## PASS
The site structure is specific to the niche and can be implemented without inventing business facts.
